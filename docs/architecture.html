Noesis architecture

Nov 26, 2026@coconutupdated: flashcards, slides, study tools, CPU/GPU embeddings

Overview

Noesis is a local study assistant. An Angular app calls a FastAPI backend, which stores PDFs on disk and in Postgres with pgvector, embeds text locally with Qwen3, and asks Groq for cited answers, quizzes, flashcards and slide decks.

  • Frontend: Frontend/Noesis/src/app (Angular 22, standalone components, signals, OnPush).
  • Backend: Backend/src/backend (FastAPI, SQLAlchemy 2, Alembic, python-pptx). Paths below are relative to these two folders unless written in full.
  • Database: Postgres 17 + pgvector in Docker (Backend/docker-compose.yml), schema in Backend/alembic/versions/0001 to 0006.
  • Models: Qwen3-Embedding-0.6B runs locally on a usable GPU, otherwise on the CPU in fp32 with a measured thread count. Groq (llama-3.3-70b-versatile) writes every generated text.
  • Auth is off: every request acts as one local user, created in api/dependencies.py:27 (get_current_user).
  • One-click scripts in the repository root: setup.bat downloads everything, run-noesis.bat starts Docker, the database, backend and frontend.

Line numbers point at where each class or function starts, as of this date. Items marked new were added since the Nov 12 version.

Backend classes

The backend has three groups of classes: database models that hold the data, service modules that hold the logic, and provider classes behind interfaces so the embedder and LLM can be swapped.

Data model

A user owns documents, conversations, quizzes, flashcard decks and slide decks. A document is split into pages and chunks. Everything generated from a PDF (message sources, quiz questions, flashcards, slide citations) keeps a snapshot of filename and page, so it survives deleting the document.

Choosing the embedding device new

The first upload or question loads the model. torch.cuda.is_available() can be true for a GPU the installed PyTorch cannot run (an RTX 50-series card with a cu126 build), so a tiny test operation decides. On the CPU, fp32 with one text per pass and the measured thread count is about 13 times faster than the bf16 default on a Ryzen 5 5600.

Reader new

The reader opens at an explicit ?page= (citations, quiz review) or else at the last page read in this browser (noesis.lastPage.<id>, saved 400 ms after scrolling stops). Search loads each page's text once with pdf.js, highlights matches in their own colour so citation highlights stay, and notes image-only pages that have no searchable text. Download fetches /documents/{id}/file and saves it under the original filename.

Status updates: polling

LibraryPage calls GET /documents every 2.5 seconds, but only while at least one PDF is pending or processing, and stops once all are completed, failed or missing.

  • Interval: POLL_MS = 2500 at features/library/library-page.ts:15; the setInterval is at library-page.ts:110.
  • Progress bars use progress_done / progress_total, saved after each embedding batch.
  • Chat and the generators do not poll; they wait for the HTTP response.
